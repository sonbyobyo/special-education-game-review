# 특수교육 학습게임 검수

특수교육대상자가 사용하는 학습게임·웹앱을 목표, 접근성, 의사소통, 감각 조절, 수업 운영과 정보 보호의 관점에서 검수하는 Codex 스킬입니다. 현재 버전은 v1.1이며 조사 기준일은 2026-10-05, 검사 절차·기록 형식 개정일은 2026-10-06입니다.

스킬은 Codex에 검수 기준과 절차를 제공합니다. 브라우저 도구가 제공되고 사이트에 접근할 수 있는 환경에서는 실제 웹사이트를 열어 조작할 수 있습니다. URL, 설계안, 소스, 실기기·학생 관찰 자료 중 제공된 자료에 따라 검수 범위를 구분합니다.

항목별 결과는 **통과 / 수정 필요 / 미확인 / 해당 없음**이며 근거, 적용 조건, 검사 범위와 다음 검사를 함께 기록합니다. 문헌 근거와 실제 제품 관찰 증거를 구분합니다.

56개 ID는 유지하되 **제품 54개와 검수 기록 품질 R11/R12를 별도 집계**합니다. 검수 기록 통과를 제품 통과 개수에 더하지 않습니다.

v1.1은 정상 완료 외에 과제별 오답·반례·회복을 검사하고, 실제 구성·설명·성공 판정의 일치를 확인합니다. 입력 대안은 기능 동등성과 학습 행동 보존을 구분합니다. 차단 조건과 미확인 사유·다음 행동·담당을 기록하며, 검수 문서를 제품 코드 검토 증거로 분류하지 않습니다. [실제 활동 검사 절차](skills/special-education-game-review/references/activity-checks.md)에 구체적인 예와 적용 예외가 있습니다.

## 설치와 사용

설치할 폴더는 `skills/special-education-game-review`입니다. `SKILL.md`, `agents`, `references`, `scripts`를 함께 설치해야 합니다.

Codex에서 다음처럼 요청할 수 있습니다.

> https://github.com/sonbyobyo/special-education-game-review/tree/main/skills/special-education-game-review 에 있는 스킬을 설치해 줘.

직접 설치할 때는 위 폴더를 Codex 사용자 스킬 디렉터리의 `special-education-game-review` 폴더로 복사합니다. 기본 사용자 스킬 디렉터리는 `~/.codex/skills`이며 `CODEX_HOME`을 별도로 설정했다면 해당 디렉터리의 `skills`를 사용합니다. 설치 후 새 세션에서 스킬 인식을 확인합니다.

호출 예시:

> $special-education-game-review로 [웹사이트 URL]을 검수해 줘. 목표는 [확인된 목표 또는 교사 제안]이고, [핵심 활동]을 확인해 줘.

설계안만 제공할 수도 있습니다. 이 경우 예정 기능과 구현 기능을 구분하고, 설계 수정 제안과 구현 후 시험 목록을 반환합니다. 학생 실명·진단명·IEP 원문을 입력할 필요는 없습니다.

## 선택적 기록 도구

Node.js 18 이상에서 스킬 폴더를 작업 디렉터리로 사용합니다.

```bash
node scripts/review.mjs init --output intake.json
# intake.json에 목표·범위·기능의 확인 근거를 작성
node scripts/review.mjs draft --input intake.json --output review.json
# 실제 검수를 수행해 review.json의 증거·판정을 작성
node scripts/review.mjs validate --input review.json
node scripts/review.mjs summary --input review.json
node scripts/review.mjs report --input review.json --output report.md
node scripts/review.mjs csv --input review.json --output criteria.csv
```

도구는 미확인 초안과 기록 검증을 제공합니다. 웹사이트의 실행·관찰·판단은 Codex와 사용 가능한 검수 도구가 수행합니다. 기존 출력 파일은 덮어쓰지 않습니다. Node.js가 없어도 계약에 따라 수동 기록할 수 있습니다.

v1.1 기록에는 실제/계획 검사 시나리오, 항목별 확인·미검사 범위, 증거 대상, 미확인 사유가 포함됩니다. `validate`는 기록의 구조와 연결을 검사하며 학습 내용의 참·거짓이나 교육 효과를 자동 판단하지 않습니다. v1 결과는 원본을 보존하고 새 사본에서 필요한 필드를 대조합니다. 버전 문자열만 바꾸면 새 기록 요건을 충족하지 않습니다. 새 실행이 없으면 기존 관찰 재분류로 표시합니다.

## 현재 범위와 검증

v1 제작 과정에서 판정 도구의 경계 검사 17개와 실제 웹앱·설계 문서 두 사례의 적용 시험을 수행했습니다. 이는 스킬의 절차와 기록 도구를 확인한 결과입니다. 적용 사례의 설계 전체나 제품 전체가 통과했다는 뜻은 아닙니다.

v1.1에서는 기록 도구·시나리오 연결·제품/검수 기록 분리·반례 적용·입력 대안·CLI 출력의 자동 검사 32개를 수행했습니다. 결함·수정·창작 사례는 **합성 기록의 판정 경계 검사**이며 실제 제품에서의 탐지 성능 시험이 아닙니다. 추가 실제 수학 사이트의 기존 브라우저 관찰 기록도 새 형식으로 재분류했습니다. 실제 학생 효과, 독립 검수자의 탐지율·오탐률·반복 일치도는 검증하지 않았습니다.

재현 가능한 기록 도구 검사:

```bash
node --test scripts/tests/review.test.mjs
```

- 통과는 확인한 항목·활동·버전·환경에 한정합니다. 부분 검사, 코드 또는 화면만으로 학생 이해·선호·학습 효과를 확정하지 않습니다.
- 실제 학생, AAC·스위치·화면 읽기 프로그램, 수업 실기기 검증은 별도 관찰·시험이 필요합니다.
- 전체 WCAG/KWCAG 적합성 인증, 법적 적합성 판정, 모든 학생 사용 가능성이나 학습 효과의 보증을 제공하지 않습니다.
- 현재 기준은 목표·기능·지원·접근성 검수 중심입니다. 핵심 학습 내용의 충분성, 경험의 깊이, 난이도 진행과 교사 중재 체계에 대한 설계 평가 기준은 보강할 부분입니다.
- 공식 IEP 목표·성취기준을 추정 생성하지 않습니다. 교사 제안 목표는 그 지위를 유지합니다.

## 출처와 이용 조건

원장에는 출처 URL, 문헌 지위, 확인 시점과 해석 범위가 기록되어 있습니다. 표준 요구, 전문 권장과 프로젝트 검수 제안을 구분합니다. 원문 전체·학생 자료·외부 이미지·폰트·음성 자산은 이 저장소에 포함하지 않습니다.

이 저장소의 별도 재배포 라이선스는 아직 지정하지 않았습니다. 참조 문헌과 외부 자산의 이용 조건은 각 권리자의 원 조건을 따로 확인해야 합니다.
