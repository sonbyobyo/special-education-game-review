# 실제 활동 검사 절차 v1.1

56개 기준을 실행할 때 사용하는 프로젝트 검사 절차이다. 새로운 법적 의무나 모든 게임에 동일한 정답을 강제하는 규칙이 아니다. 결과 필드는 [입력·판정 계약](review-contract.md)을 따른다.

## 활동과 검사 범위

주요 활동마다 학생이 해야 할 판단, 입력, 종료 조건을 먼저 적는다. 시작→응답→피드백→다시하기→종료의 대표 경로를 실행하고, 해당 활동에 있는 도움·취소·복귀를 추가한다. 입력 방식이 다르면 각각 검사한다. 좁은 화면·확대·모달·저장 복원 등은 관련 기능이 있을 때 선택한다. 모든 조합을 기계적으로 곱하지 말고 핵심 판단과 조작이 달라지는 경로를 우선한다.

- 한 코스 첫 단계 완료는 상위 단계·무작위 문항 전체 완료가 아니다.
- 특정 입력에서 완료되더라도 다른 입력·기기까지 통과로 확대하지 않는다.
- 정상·오답·반례·회복 중 무엇을 실제 실행했는지 checks에 적는다. 미실시 시험은 planned/not_run이며 통과 증거가 아니다.
- 화면 전환·저장 복원·리사이즈 직후 상태는 안정 상태와 대조한다. 도구 실패만 있으면 제품 결함으로 단정하지 않는다.
- 공유 기기 상태 변경은 모의 자료로 검사한다. 기존 기록을 무조건 초기화하거나 삭제하지 않는다.

## G03: 실제 구성과 피드백의 일치

수량·분류·순서·관계·절차를 판단하는 활동에는 정상 상태와 가능한 오답 또는 반례를 선택한다. 화면 문구, 실제 객체 상태, 학생 응답, 성공 판정을 서로 대조한다. 정답 숫자가 맞아도 실제 구성 설명이 틀리면 이를 별도 결함으로 기록한다.

| 과제 | 대표 반례 후보 | 대조할 내용 |
|---|---|---|
| 똑같이 나누기 | 총수는 같지만 대상별 수량은 다른 배치 | 실제 그릇별 수량과 공평 설명·성공 여부 |
| 묶음 세기 | 총수는 같지만 묶음 크기가 다른 배치 | 묶음별 개수·묶음 수·곱셈 설명 |
| 분류·순서 | 수/항목은 맞지만 위치·범주가 다른 상태 | 제출 상태·지시·오류 설명 |
| 선택형 문항 | 오답 선택 후 정답 재시도 | 오답 회복, 최초 응답과 완료 건수의 구분 |

예: 10개를 9/1로 배치하고 몫 5를 고르는 시험에서는 계산 10÷2=5와 구성 9≠1을 구분한다. 9/1을 공평하다고 설명하는 결함이 수정됐다면 과거 결함을 그대로 재사용하지 말고 새 상태·피드백을 기록한다.

반례를 만들 수 없는 제한된 UI라면 그 제한과 입력 경로를 적는다. 창작·탐색·선호 활동에는 유일 정답을 강제하지 않는다. 물레 모양이나 그림이 예시와 다르다는 이유만으로 오답으로 만들지 말고 자료·물리 관계·절차 설명의 사실 정확성을 확인한다.

## A02와 G01/G02: 입력 대안 비교

드래그와 비드래그 포인터 대안을 실제 실행하고 다음을 분리한다.

1. **기능 동등성**: 같은 대상·목적지·수량·순서·수정 행동을 사용자가 선택할 수 있는가? 드래그가 제공하는 기능을 클릭 경로에서도 완료하는지 A02로 판단한다. 단순히 다음 화면에 도착했다는 이유로 통과시키지 않는다. 키보드 경로는 A01로 따로 검사한다.
2. **학습 행동 보존**: 목표 기술을 학생이 수행하는가, 프로그램이 대신 수행하는가? G01/G02와 확인된 목표를 대조한다. 예를 들어 목표가 몫 선택이라면 자동 배치가 접근 도움일 수 있지만 목표가 공평 분배 구성이라면 자동 배치는 목표 기술을 대행할 수 있다.

equivalence.operation과 equivalence.learning_action에 각각 confirmed/different/unknown/not_applicable을 기록한다. 기능 비교만 확인됐으면 학습 행동은 unknown으로 둘 수 있다. 교사 목표가 없다는 이유만으로 확인한 기능 비교까지 지우거나, 학습 행동의 차이를 곧바로 WCAG 위반이라고 선언하지 않는다.

같은 기능을 드래그 없는 단일 포인터로 제공하는 요구와 키보드 요구는 별도로 평가한다. 근거: [W3C SC 2.5.7 해설](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html), 2026-10-06 확인. 학습 행동 비교는 프로젝트 검수 제안이다.

## 결함과 미확인의 기록

결함은 사전 상태, 실제 입력 순서, 기대 결과, 실제 결과, 증거를 연결한다. 무작위 문항이면 나온 문제·선택지·배치도 기록한다. blocker는 차단된 활동·입력·화면/기기 조건과 대체 경로를 적는다. 폭 320px에서 차단된 상태를 모든 기기에서의 차단으로 확대하지 않는다.

미확인은 다음 행동을 정할 수 있게 분류한다.

| reason | 사용 상황 | 다음 행동의 예 |
|---|---|---|
| missing_material | 목표·운영 정책·자료가 없음 | 교사가 목표 기술 확인 |
| not_tested | 가능한 검사를 아직 실행하지 않음 | 검수자가 200% 글자 확대 실행 |
| tool_limit | 접근 차단·도구 제한으로 관찰 불가 | 가능한 입력/관찰 도구에서 재시험 |
| learner_device_observation | 학생·실기기·보조공학 관찰 필요 | 교사와 합의한 실제 환경에서 관찰 |
| specialist_judgment | 측정·권리·전문 판단이 필요 | 담당자가 해당 자료와 적용 조건 대조 |

검사가 추가로 가능한 항목과 현장 관찰이 필요한 항목을 섞어 보고하지 않는다. 미확인 수를 실패 개수로 해석하거나, 미확인을 줄이려고 통과 조건을 낮추지 않는다.
